# 1107. New Users Daily Count - Go

## Go implementation notes
This is a SQL problem, so the Go file stores the accepted SQL as a raw string constant. In production Go, this would be passed to `database/sql` as a query string.

## Core idea
A new user is counted on the date of their first `login`. First compute each user's minimum login date, then count only those first-login dates in the required 90-day window.

## Algorithm
1. Filter `Traffic` to `activity = 'login'`.
2. Group by `user_id` and take `MIN(activity_date)` as `first_login`.
3. Keep rows where `first_login` is between `DATE_SUB('2019-06-30', INTERVAL 90 DAY)` and `2019-06-30`.
4. Group by `first_login` and count users.

## Data structure choice
This is a SQL aggregation problem. The grouped subquery acts like a per-user hash map from user to earliest login date.

## Correctness argument
The inner query assigns exactly one first login date to each user. The outer filter removes users whose first login is outside the reporting window, and grouping by that date counts exactly the users who became new on each output date.

## Complexity
Database cost depends on indexes, but logically the query scans login rows once and groups by user, then by date. An index on `(activity, user_id, activity_date)` would help.

## Tests and edge cases
- Users with only non-login activity are ignored.
- Multiple logins by one user count once on the earliest login date.
- A first login on `2019-04-01` or `2019-06-30` is included.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
