# 1197. Minimum Knight Moves

## Core idea
The board is unweighted, so BFS gives the minimum number of knight moves. Symmetry lets us search only around the positive target quadrant.

## Algorithm
1. Convert target to `(abs(x), abs(y))`.
2. BFS from `(0, 0)` over the eight knight moves.
3. Restrict search to `[-2, x+2]` and `[-2, y+2]`; the two-cell padding covers moves that briefly step outside the target quadrant.
4. Return the distance when the target is first reached.

## Data structure choice
A queue stores BFS states and a set stores visited coordinates.

## Correctness argument
BFS explores all positions at distance `d` before distance `d+1`, so the first target reach is minimal. Symmetry preserves distances, and the padded bounds are sufficient for constrained targets because any optimal path does not need to wander farther away than two squares past the target axes.

## Complexity
For constraints `|x|+|y| <= 300`, the bounded grid is constant-sized relative to the limit. More generally time and space are `O((x+5)(y+5))` after symmetry.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- `(2,1)` returns `1`.
- `(0,0)` returns `0`.
- Small awkward targets like `(1,1)` need two moves and validate negative padding.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
