# 1166. Design File System

## Core idea
A path can be created only if its parent path already exists. A hash map from full path to value is enough.

## Algorithm
1. Store the root as an empty string sentinel.
2. `createPath` rejects existing paths.
3. Find the parent with `rsplit('/', 1)` and reject if missing.
4. Insert the new path and value; `get` is a dictionary lookup with default `-1`.

## Data structure choice
A dictionary gives expected constant-time path existence and value lookup.

## Correctness argument
The parent check enforces the file-system creation rule. Since every successful creation stores the exact full path, future `get` and child creation queries observe precisely the created paths.

## Complexity
Each operation is `O(L)` for path string processing/hash, where `L` is path length. Space is `O(number of created paths)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Creating `/a/b` before `/a` fails.
- Creating the same path twice fails.
- `get` on missing path returns `-1`.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
