# 1152. Analyze User Website Visit Pattern - Java

## Java implementation notes
Visits are sorted through an `Integer[]` index order. Per-user sequences use `List<String>`, and patterns are counted with `Map<List<String>, Integer>`.

## Core idea
For each user, generate the set of distinct 3-site sequences they visited in chronological order. Count how many users produced each pattern.

## Algorithm
1. Sort all visits by timestamp.
2. Build each user's ordered website list.
3. Generate all 3-combinations of that user's list and deduplicate them per user.
4. Count patterns across users and choose highest count, breaking ties lexicographically.

## Data structure choice
A dictionary groups visits by user; a `Counter` tracks pattern popularity; per-user sets prevent duplicate counting for one user.

## Correctness argument
Sorting gives the true visit order. Combinations preserve chronological order and enumerate every possible 3-sequence for that user. Counting each user once per pattern matches the problem definition, and the final comparator implements the required tie-break.

## Complexity
If a user has `v` visits, generating patterns costs `O(v^3)`. Constraints are small enough for this. Space stores visits and generated patterns.

## Tests and edge cases
- Duplicate pattern from one user counts once.
- Tie counts choose lexicographically smaller pattern.
- Users with fewer than three visits contribute nothing.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
