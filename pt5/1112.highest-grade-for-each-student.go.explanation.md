# 1112. Highest Grade For Each Student - Go

## Go implementation notes
This is a SQL problem, so the Go file contains the SQL query as a raw string constant. The query itself uses a window function rather than an in-memory Go structure.

## Go interview framing

Then walk through how the code mutates that representation while preserving the invariant.

## Core idea
Rank each student's enrollments by highest grade first and smallest course id second, then keep rank one.

## Algorithm
1. Use `ROW_NUMBER()` partitioned by `student_id`.
2. Order each partition by `grade DESC, course_id ASC`.
3. Select only rows with `row_num = 1`.
4. Order the final result by `student_id`.

## Data structure choice
The database's window function maintains the ordered partition for each student.

## Correctness argument
The ordering exactly matches the problem's priority: highest grade wins, and ties choose the smallest course. Row number one in each partition is therefore the unique required row for that student.

## Complexity
Logically this groups/sorts enrollments per student. With an index on `(student_id, grade, course_id)`, the database can execute it efficiently.

## Interview explanation

## Tests and edge cases
- A student with one course returns that course.
- Tied grades choose the smaller `course_id`.
- Students are emitted in increasing `student_id` order.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
