# 1186. Maximum Subarray Sum With One Deletion - Go

## Go implementation notes
Two rolling integer DP states replace a table: best ending here with no deletion and with one deletion.

## Go interview framing
In Go, explain both the algorithmic invariant and the concrete representation: slices for dense arrays/queues/stacks, maps for sparse lookup, structs for queue states or records, and channels or `sync` primitives for concurrency. Then walk through how the code mutates that representation while preserving the invariant.

## Core idea
Track the best subarray ending here with no deletion and with one deletion already used.

## Algorithm
1. `no_delete` is Kadane's best sum ending at current index without deletion.
2. `one_delete` is best sum ending here after deleting one element somewhere.
3. For each value, either extend a previous one-deletion subarray or delete the current value from a no-deletion subarray.
4. Update the global best from both states.

## Data structure choice
Two rolling DP variables replace a full DP table.

## Correctness argument
Every optimal subarray ending at the current position either has not deleted anything, has deleted earlier and includes the current value, or deletes the current value. The transitions cover exactly those cases while preserving non-empty subarrays.

## Complexity
Time is `O(n)`, space is `O(1)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- All-negative arrays return the largest single element.
- `[1,-2,0,3]` returns `4` by deleting `-2`.
- Deleting is optional, so normal Kadane cases still work.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
