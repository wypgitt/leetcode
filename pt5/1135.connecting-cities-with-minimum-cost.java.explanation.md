# 1135. Connecting Cities With Minimum Cost - Java

## Core idea
This is a minimum spanning tree problem. Kruskal's algorithm chooses the cheapest edges that do not create a cycle.

## Algorithm
1. Sort all connections by cost.
2. Use DSU to track connected components.
3. For each edge, union its endpoints; if they were separate, add the edge cost.
4. When `n - 1` edges are used, return the total. If impossible, return `-1`.

## Data structure choice
Disjoint Set Union with path compression and union by rank gives fast cycle checks.

## Correctness argument
By the cut property of MSTs, the cheapest edge crossing any cut is safe to add. Kruskal repeatedly adds the cheapest safe edge, so the resulting connected acyclic graph is a minimum spanning tree when one exists.

## Complexity
Sorting dominates: `O(m log m)` time. DSU space is `O(n)`.

## Tests and edge cases
- Disconnected graph returns `-1`.
- Already connected with extra expensive edges ignores cycles.
- Single city needs no edges, though constraints commonly provide `n >= 1`.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
