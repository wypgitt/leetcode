# 1115. Print FooBar Alternately - Java

## Java implementation notes
Two `Semaphore` objects model turn ownership. `fooTurn` starts with one permit and `barTurn` starts with zero.

## Core idea
Two semaphores represent whose turn it is. `foo` starts available and `bar` starts blocked.

## Algorithm
1. `foo_turn` is initialized to 1 and `bar_turn` to 0.
2. Each `foo` iteration acquires `foo_turn`, prints, then releases `bar_turn`.
3. Each `bar` iteration acquires `bar_turn`, prints, then releases `foo_turn`.

## Data structure choice
Semaphores are the right synchronization primitive because each print hands exactly one permit to the other thread.

## Correctness argument
At the start only `foo` can print. After every `foo`, only `bar` can print; after every `bar`, only `foo` can print. This invariant forces the output to be `foobar` repeated `n` times.

## Complexity
Each method performs `n` acquire/print/release cycles. Time is `O(n)` and extra space is `O(1)`.

## Tests and edge cases
- `n = 1` prints `foobar`.
- `n = 2` prints `foobarfoobar`.
- Starting the `bar` thread first still blocks until `foo` prints.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
