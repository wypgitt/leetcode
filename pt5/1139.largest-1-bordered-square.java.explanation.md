# 1139. Largest 1-Bordered Square - Java

## Java implementation notes
Two `int[][]` DP tables store horizontal and vertical runs of ones ending at each cell.

## Core idea
Precompute consecutive ones ending at each cell horizontally and vertically. Then each possible bottom-right corner can validate a border in constant time.

## Algorithm
1. For every cell, compute `horizontal[r][c]` and `vertical[r][c]` if the cell is `1`.
2. Treat each `1` as a possible bottom-right corner.
3. The largest candidate side cannot exceed the smaller of its horizontal and vertical counts.
4. Check whether the top border and left border also have enough consecutive ones.

## Data structure choice
Two DP grids store local run lengths of ones.

## Correctness argument
A square border is all ones exactly when its bottom and right borders fit at the bottom-right corner and its top and left borders have the same side length. The precomputed runs test those four borders exactly.

## Complexity
Time is `O(m*n*min(m,n))` in the worst case; space is `O(m*n)`.

## Tests and edge cases
- All-zero grid returns `0`.
- A single one returns area `1`.
- Interior zeros do not matter if the border is all ones.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
