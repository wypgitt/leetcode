# 1155. Number Of Dice Rolls With Target Sum - Go

## Go implementation notes
A one-dimensional `[]int` DP slice is rebuilt for each die. The modulo is applied per state.

## Go interview framing
In Go, explain both the algorithmic invariant and the concrete representation: slices for dense arrays/queues/stacks, maps for sparse lookup, structs for queue states or records, and channels or `sync` primitives for concurrency. Then walk through how the code mutates that representation while preserving the invariant.

## Core idea
Dynamic programming counts ways to reach every sum after each number of dice.

## Algorithm
1. `dp[sum]` is the number of ways after the processed dice.
2. Start with `dp[0] = 1` before rolling any dice.
3. For each die, build `next_dp[total]` by trying every face value that can lead to `total`.
4. Take modulo `1e9 + 7` at each state.

## Data structure choice
A one-dimensional DP array is enough because each die only depends on the previous die count.

## Correctness argument
Every way to make `total` after a new die consists of a previous total `total - face` plus the chosen face. Summing over all legal faces partitions all possibilities exactly once.

## Complexity
Time is `O(n*k*target)`, space is `O(target)`.

## Tests and edge cases
- Impossible targets such as too small or too large naturally produce `0`.
- `n=1` checks direct face availability.
- Large answers require modulo handling.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
