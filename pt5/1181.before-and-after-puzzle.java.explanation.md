# 1181. Before And After Puzzle - Java

## Java implementation notes
A `HashSet<String>` removes duplicate puzzles and an `ArrayList<String>` is sorted before returning.

## Java interview framing
In Java, call out the concrete collection or primitive array that carries the invariant. Arrays are best for dense indexed state, `HashMap`/`HashSet` for sparse lookup, `ArrayDeque` for queues and stacks, `PriorityQueue` for greedy minimum extraction, and `Semaphore`/monitor methods for concurrency. ## Core idea
Try every ordered pair of phrases. When the last word of the first equals the first word of the second, merge them with that word only once.

## Algorithm
1. Split every phrase into words.
2. For each pair `i != j`, compare `words[i][-1]` with `words[j][0]`.
3. If they match, append the second phrase without its first word to the first phrase.
4. Store in a set to remove duplicates, then return sorted results.

## Data structure choice
A set handles distinct puzzle strings; pre-split word lists avoid repeated parsing.

## Correctness argument
The problem allows every ordered pair of different phrases, and the algorithm checks exactly those pairs. The merge operation preserves all words while combining the shared boundary word once, so every generated string is valid and every valid pair is generated.

## Complexity
There are `O(n^2)` pairs and phrase lengths are bounded. Space is `O(number of puzzles)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Duplicate phrases can generate the same output once.
- Order matters, so both directions are checked.
- Single-word second phrases merge without adding trailing spaces.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
