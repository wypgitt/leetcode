# 1109. Corporate Flight Bookings

## Core idea
Range additions are ideal for a difference array: add seats at the start of the interval and subtract them just after the interval.

## Algorithm
1. Create `diff` of length `n + 1`.
2. For booking `[first, last, seats]`, add `seats` to `diff[first - 1]` and subtract `seats` from `diff[last]`.
3. Take a running prefix sum through the first `n` positions to recover each flight's reserved seats.

## Data structure choice
The difference array compresses many range updates into two point updates each.

## Correctness argument
A booking contributes to every prefix position from `first - 1` through `last - 1` because the added value remains in the running sum until the subtraction at `last`. Summing all booking effects gives exactly the total seats per flight.

## Complexity
Time is `O(n + m)` for `m` bookings. Space is `O(n)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- The sample returns `[10,55,45,25,25]`.
- A booking ending at flight `n` works because `diff[n]` is the sentinel subtraction.
- Overlapping bookings add naturally.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
