# 1124. Longest Well-Performing Interval

## Core idea
Convert tiring days to `+1` and others to `-1`. A well-performing interval has positive sum.

## Algorithm
1. Maintain prefix score as you scan days.
2. If current score is positive, the interval from day `0` is valid.
3. Otherwise, look for the earliest index where prefix score was `current - 1`; the subarray after it has positive sum.
4. Store only the first occurrence of each score to maximize interval length.

## Data structure choice
A hash map from prefix score to earliest index gives constant-time interval lookups.

## Correctness argument
An interval sum is the difference of two prefix scores. Positive sum means the earlier prefix is smaller. Because scores move by one, finding `score - 1` is enough to find a valid smaller prefix, and the earliest such prefix gives the longest interval ending here.

## Complexity
Time is `O(n)`, space is `O(n)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Sample `[9,9,6,0,6,6,9]` returns `3`.
- All non-tiring days return `0`.
- All tiring days return the whole length.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
