# 1188. Design Bounded Blocking Queue - Java

## Java implementation notes
`Semaphore` objects count empty slots and available items, while `ReentrantLock` protects the `ArrayDeque<Integer>`.

## Core idea
Use a condition variable to block producers while full and consumers while empty.

## Algorithm
1. Protect the deque with one `Condition` lock.
2. `enqueue` waits while size equals capacity, then inserts at the front and notifies waiters.
3. `dequeue` waits while empty, then removes from the rear and notifies waiters.
4. `size` reads the queue length under the same lock.

## Data structure choice
A deque supports front insertion and rear removal. A condition variable provides blocking and wake-up behavior.

## Correctness argument
All queue mutations happen while holding the lock, so size checks and updates are atomic. The while-loops recheck conditions after wake-up, preventing spurious wakeups from violating capacity or emptiness rules.

## Complexity
Ignoring blocking time, each operation is `O(1)` and space is `O(capacity)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Dequeuing from an empty queue blocks until enqueue.
- Enqueuing into a full queue blocks until dequeue.
- Concurrent size reads observe a consistent length.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
