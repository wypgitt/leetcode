# 1123. Lowest Common Ancestor of Deepest Leaves - Go

## Go implementation notes
The recursive helper returns `(depth, *TreeNode)`, a compact Go tuple-like multiple return that avoids a custom result struct.

## Go interview framing
In Go, explain both the algorithmic invariant and the concrete representation: slices for dense arrays/queues/stacks, maps for sparse lookup, structs for queue states or records, and channels or `sync` primitives for concurrency. Then walk through how the code mutates that representation while preserving the invariant.

## Core idea
For each subtree, return both its maximum depth and the LCA of deepest leaves inside it.

## Algorithm
1. DFS returns `(depth, lca)` for the current subtree.
2. If left and right depths are equal, deepest leaves exist on both sides, so the current node is their LCA.
3. If one side is deeper, the answer for the current subtree is that side's LCA.
4. Return the chosen LCA with depth increased by one.

## Data structure choice
Recursive postorder traversal is the natural structure because LCA depends on child depths.

## Correctness argument
The deepest leaves of a subtree are either all on the deeper child side or split across both sides when depths tie. The algorithm mirrors exactly those cases, so each returned LCA is correct by induction.

## Complexity
Each node is visited once: `O(n)` time and `O(h)` recursion space.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- A one-node tree returns the root.
- If only one deepest leaf exists, it returns that leaf.
- If deepest leaves are on both sides, it returns their lowest meeting node.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
