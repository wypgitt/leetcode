# 1167. Minimum Cost To Connect Sticks

## Core idea
This is the same greedy structure as Huffman coding: always merge the two shortest sticks first.

## Algorithm
1. Heapify all stick lengths.
2. Repeatedly pop the two smallest lengths.
3. Add their sum to the total cost and push the merged length back.
4. Stop when one stick remains.

## Data structure choice
A min-heap efficiently returns the two smallest current sticks after every merge.

## Correctness argument
In an optimal merge tree, the two smallest sticks can be siblings at maximum depth; merging them first never increases total cost. Reapplying this exchange argument after each merge yields the greedy optimum.

## Complexity
There are `n-1` merges, each using heap operations: `O(n log n)` time and `O(n)` space.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- One stick costs `0`.
- `[2,4,3]` returns `14`.
- Large sticks still work because Python integers do not overflow.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
