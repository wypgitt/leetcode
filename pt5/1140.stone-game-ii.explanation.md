# 1140. Stone Game II

## Core idea
Use minimax DP. From state `(i, M)`, the current player can take `X` piles and then the opponent plays optimally from the next state.

## Algorithm
1. Build suffix sums so remaining stones from `i` are known in `O(1)`.
2. Define `best_from(i, M)` as the maximum stones current player can get from piles `i..end`.
3. If `2M` covers all remaining piles, take all.
4. Otherwise try every `X` from `1` to `2M` and maximize `suffix[i] - best_from(i+X, max(M, X))`.

## Data structure choice
Memoized recursion stores game states; suffix sums avoid recomputing totals.

## Correctness argument
For each legal move, the opponent receives their optimal amount from the remaining stones. The current player gets total remaining minus that amount. Choosing the maximum over all legal moves is exactly optimal play.

## Complexity
There are `O(n^2)` states and up to `O(n)` transitions per state, commonly accepted for `n <= 100`. Space is `O(n^2)` for memoization.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Sample `[2,7,9,4,4]` returns `10`.
- If `2M` reaches the end, current player takes everything.
- One pile returns that pile.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
