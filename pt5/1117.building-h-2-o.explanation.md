# 1117. Building H2O

## Core idea
Limit each molecule to two hydrogen threads and one oxygen thread, then use a barrier so the three threads complete as a group.

## Algorithm
1. A hydrogen semaphore has two permits; an oxygen semaphore has one.
2. Each thread acquires its element permit, calls the release function, waits at a reusable barrier of size three, then releases its permit.
3. Because permits are not released until the barrier opens, the next molecule cannot overtake the current incomplete group.

## Data structure choice
Semaphores enforce the H:H:O ratio. A barrier enforces molecule-sized batches.

## Correctness argument
At most two hydrogen threads and one oxygen thread can enter a batch. The barrier opens only when all three have arrived, so every emitted group has exactly `HHO` in some order before permits allow the next group.

## Complexity
Each thread does constant synchronization work. Space is `O(1)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Input `HOH` forms one complete molecule.
- `OOHHHH` forms two groups of three.
- Many hydrogen threads arriving first block after two permits are used.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
