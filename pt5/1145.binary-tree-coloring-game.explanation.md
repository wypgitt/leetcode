# 1145. Binary Tree Coloring Game

## Core idea
After the first player colors node `x`, the second player can choose one of three regions: left subtree, right subtree, or the parent-side remainder.

## Algorithm
1. DFS to compute subtree sizes.
2. When node `x` is found, record sizes of its left and right subtrees.
3. The parent-side region size is `n - left - right - 1`.
4. The second player wins iff any region has more than half the nodes.

## Data structure choice
DFS is used for subtree sizes; no extra tree structure is needed.

## Correctness argument
Once the second player chooses a node in one of the three regions adjacent to `x`, the first player cannot cross through `x` to enter that region. Therefore owning a region larger than `n/2` guarantees more colored nodes, and no smaller region can guarantee a majority.

## Complexity
Time is `O(n)`, recursion space is `O(h)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- If `x` is root, only left and right regions matter.
- If one child subtree has majority, second wins.
- Balanced regions of size at most half return false.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
