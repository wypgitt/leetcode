# 1182. Shortest Distance To Target Color

## Core idea
Store sorted positions for each of the three colors. The nearest target color to an index is the closest position around the binary-search insertion point.

## Algorithm
1. Build `positions[color]` lists by scanning `colors` once.
2. For each query, binary-search the target color's position list.
3. Check the candidate at the insertion point and the one before it.
4. Return the smaller distance, or `-1` if the color does not exist.

## Data structure choice
Three sorted arrays are natural because positions are discovered in increasing order.

## Correctness argument
In a sorted list, the closest value to a target must be either the first value not less than it or the previous value. Checking both therefore finds the shortest distance to that color.

## Complexity
Preprocessing is `O(n)`. Each query is `O(log n)`. Space is `O(n)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Color absent returns `-1`.
- If index already has target color, distance is `0`.
- Targets at array ends check one-sided candidates.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
