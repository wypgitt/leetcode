# 1177. Can Make Palindrome From Substring

## Core idea
A string can be rearranged into a palindrome if at most one character has odd count. Each replacement can fix two odd counts.

## Algorithm
1. Build prefix parity bitmasks over the string.
2. For a query `[l, r, k]`, XOR prefix masks to get odd/even parity in the substring.
3. Count set bits to know how many characters have odd counts.
4. The needed replacements are `odd_count // 2`; compare with `k`.

## Data structure choice
A 26-bit integer mask stores count parity compactly.

## Correctness argument
Rearrangement ignores order, so only character count parity matters. Pairing odd-count characters requires one replacement per pair, and one odd may remain in the center. Thus `odd_count // 2 <= k` is necessary and sufficient.

## Complexity
Prefix build is `O(n)`. Each query is `O(1)` over a fixed alphabet. Space is `O(n)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Length-one substrings are always true.
- `k = 0` tests pure palindrome-permutation condition.
- Large `k` always succeeds for the substring.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
