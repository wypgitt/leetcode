# 1116. Print Zero Even Odd

## Core idea
Use one semaphore for zero and one for each number parity. Zero decides whether the next number should be odd or even.

## Algorithm
1. `zero_turn` starts with one permit; `odd_turn` and `even_turn` start at zero.
2. The zero thread prints `0` before every number and releases the odd or even semaphore based on that number.
3. Odd and even threads print their assigned values and release `zero_turn` for the next cycle.

## Data structure choice
Three semaphores model the finite-state machine: zero, odd number, zero, even number, and so on.

## Correctness argument
Only zero can start. After zero prints for value `i`, exactly the semaphore for `i`'s parity is released. That number thread prints `i` and returns control to zero, so the sequence is forced to be `010203...0n`.

## Complexity
There are `2n` print operations. Time is `O(n)` and space is `O(1)`.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- `n = 2` prints `0102`.
- `n = 1` has no even-thread output.
- Threads may start in any order because semaphores gate execution.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
