# 1156. Swap For Longest Repeated Character Substring - Go

## Go implementation notes
Run-length encoding is stored as a slice of small structs, while total character counts use a fixed `[26]int` array.

## Go interview framing
In Go, explain both the algorithmic invariant and the concrete representation: slices for dense arrays/queues/stacks, maps for sparse lookup, structs for queue states or records, and channels or `sync` primitives for concurrency. Then walk through how the code mutates that representation while preserving the invariant.

## Core idea
Compress the string into runs. A swap can either extend one run by one matching character from elsewhere or bridge two same-character runs separated by exactly one different character.

## Algorithm
1. Count total occurrences of every character.
2. Build run groups `(char, length)`.
3. For each run, it can grow by one if another same character exists outside the run.
4. For every pattern `aaa b aaa` where the middle run length is one, combine the outer runs and possibly add one more from elsewhere.

## Data structure choice
Run-length encoding captures the only local structures a single swap can improve.

## Correctness argument
A single swap can affect at most one gap or one run boundary. The algorithm checks all single-run extensions and all one-character-gap bridges, which are the only ways to create a longer repeated-character block.

## Complexity
Time is `O(n)`, space is `O(n)` for groups.

## Interview explanation

Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- All same characters return length `n`.
- `ababa` bridges around one-character gaps.
- If no extra matching character exists, the result is capped by total count.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
