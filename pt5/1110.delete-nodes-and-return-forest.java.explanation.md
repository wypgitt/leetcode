# 1110. Delete Nodes And Return Forest - Java

## Java implementation notes
Java uses a `HashSet<Integer>` for deleted values and an `ArrayList<TreeNode>` for forest roots. The recursive helper mutates child references directly.

## Core idea
Postorder DFS lets each node decide whether its children remain attached. When a deleted node has surviving children, those children become new roots.

## Algorithm
1. Put `to_delete` in a set for constant-time checks.
2. DFS with a flag `is_root` indicating whether the current node has no surviving parent.
3. If the node is a root candidate and is not deleted, append it to the forest.
4. Recurse into children, passing `deleted` as the next `is_root` flag, and reconnect returned child roots.
5. Return `None` for deleted nodes so parents detach them.

## Data structure choice
A hash set stores deleted values; the answer list stores forest roots. The recursion uses the tree itself for rewiring.

## Correctness argument
Every surviving node whose parent is deleted, or which is the original root, is appended exactly when visited with `is_root=True`. Deleted nodes return `None`, so no deleted node remains connected. Surviving non-root nodes stay attached to their nearest surviving parent.

## Complexity
Each node is visited once. Time is `O(n)` and space is `O(n)` in the worst case for recursion and the delete set.

## Tests and edge cases
- Deleting the original root promotes surviving children.
- Deleting a leaf only removes that leaf.
- Deleting no nodes returns the original root as the only tree.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
