# 1144. Decrease Elements To Make Array Zigzag

## Core idea
A zigzag array has valleys either at all even indices or all odd indices. Since we can only decrement, compute the cost for both patterns.

## Algorithm
1. For a chosen valley parity, each valley index must be strictly smaller than both neighbors.
2. The largest allowed value is `min(left, right) - 1`.
3. If the current value is larger, add the required decrement count.
4. Return the smaller cost between even valleys and odd valleys.

## Data structure choice
Only counters are needed; the array does not need to be modified.

## Correctness argument
In either valid zigzag pattern, exactly one parity contains all valleys. Lowering a valley to the largest allowed value is independently optimal because changing one valley does not force another valley lower. Trying both parities covers all valid zigzags.

## Complexity
Two linear scans give `O(n)` time and `O(1)` space.

## Interview explanation
Start by naming the invariant: what state is being stored and why that state is sufficient. Then explain the transition or traversal in the same order the code executes. Finally, connect the stopping condition to the returned value. This keeps the explanation grounded in the code instead of sounding like a memorized trick.

## Tests and edge cases
- Length one returns `0`.
- Already zigzag input has zero cost for one parity.
- Equal adjacent values require decrements to become strict.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
