# 1202. Smallest String With Swaps - Java

## Java implementation notes
A private DSU class groups indices, and each component stores characters in a `PriorityQueue<Character>` so the smallest available character is chosen greedily.

## Core idea
Indices connected by swap pairs form components. Within a component, characters can be permuted arbitrarily, so assign the smallest available characters to the smallest indices.

## Algorithm
1. Union every pair of swappable indices.
2. Group characters by their component root.
3. Sort each component's characters in reverse so popping gives the smallest remaining character.
4. Scan indices from left to right and pop from that index's component.

## Data structure choice
Disjoint Set Union finds connected components efficiently; grouped character lists store each component's multiset.

## Correctness argument
Swaps along connected edges allow any permutation within a component. Lexicographic minimization is greedy by index: for each index, choosing the smallest available character in its component cannot hurt later positions because later positions are less significant.

## Complexity
DSU operations are near `O(1)` amortized. Sorting characters across all groups costs `O(n log n)` total in the worst case. Space is `O(n)`.

## Tests and edge cases
- No pairs returns the original string.
- One connected component returns the globally sorted string.
- Multiple components are optimized independently.

## Possible improvements
The current solution is chosen for clarity and interview reliability. If constraints were much larger, the main improvement would be to reduce the stated bottleneck in the complexity section, while keeping the same correctness invariant.
